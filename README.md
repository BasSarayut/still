# still. — Wallpaper studio

เว็บภาษาไทยสำหรับสร้างวอลเปเปอร์ Lock Screen จากรูปและข้อความของผู้ใช้ ตามเทมเพลตเครื่องเล่นเพลงที่ตกลงไว้ ใช้งานบน iPhone และคอมพิวเตอร์ โดยไม่ต้องสมัครสมาชิก

## เริ่มใช้งาน

ต้องใช้ Node.js 22.12 ขึ้นไป (หรือ Node.js 20.19 ขึ้นไป)

```sh
npm install
npm run dev
```

เปิด `http://localhost:5173` บนคอมพิวเตอร์ ส่วน iPhone ที่ใช้ Wi-Fi เดียวกัน ให้เปิด Network URL ที่ Vite แสดงใน Terminal ต้องเปิดโปรเซส dev server ไว้และอนุญาตการเชื่อมต่อเครือข่ายในระบบปฏิบัติการ

```sh
npm run build
npm run preview
```

โฟลเดอร์ `dist/` สามารถนำไปวางบน static hosting ได้ ไม่ต้องมี backend, API key หรือ environment variables ใช้ HTTPS บนเว็บไซต์จริงเพื่อรองรับ native sharing ของเบราว์เซอร์

## สิ่งที่ทำได้

- เลือกรุ่น iPhone เพื่อกำหนดขนาด PNG และสัดส่วนพรีวิว
- อัปโหลด JPG, PNG, WebP สูงสุด 30 MB พร้อมลากวางบนคอมพิวเตอร์
- ครอปรูปเป็นสี่เหลี่ยม เลื่อนรูปบนพรีวิวด้วยเมาส์/นิ้วหรือปุ่มลูกศร และซูม 1–4 เท่า
- แก้ชื่อเพลง ศิลปิน เวลาปัจจุบัน และความยาวเพลง โดยตรวจสอบรูปแบบเวลา
- เสนอสีจากรูป 5 สี เลือกสีพื้นหลังเอง และเลือกสีข้อความ/ไอคอนหรือใช้สีอัตโนมัติ
- เปิด–ปิด Color Palette และเครดิตที่แก้ไขได้
- แสดงนาฬิกาและวิดเจ็ตจำลองเฉพาะบนพรีวิว ไม่ติดใน PNG
- ดาวน์โหลด PNG และเปิด native share เมื่อเบราว์เซอร์รองรับการแชร์ไฟล์
- บันทึกงานล่าสุดอัตโนมัติ รวมรูป ข้อความ สี การครอป และรุ่นเครื่อง

ชื่อเพลงยาวลดขนาดก่อน แล้วขึ้นได้สองบรรทัด หากยังยาวเกินพื้นที่จะตัดท้ายด้วย … ส่วนศิลปินและเครดิตจำกัดให้อยู่ภายในพื้นที่ของตัวเอง

## การจัดการรูปและข้อมูล

ใช้ React + TypeScript + Vite, Canvas 2D, IndexedDB และไอคอน Lucide ไม่มีการส่งรูปหรือข้อความออกจากเครื่อง ไม่มี analytics และฟอนต์ทดแทนให้บริการจากไฟล์ของเว็บเอง ไม่มีการเรียก Google Fonts ขณะใช้งาน

รูปที่นำเข้าจะปรับด้านยาวไม่เกิน 2,400 พิกเซลเพื่อควบคุมหน่วยความจำ และแปลงเป็น PNG ก่อนเก็บใน IndexedDB ตัวข้อมูลภาพจัดเก็บเป็น ArrayBuffer เพื่อรองรับ WebKit ในบริบทที่ไม่สามารถจัดเก็บ Blob ได้ จัดคิวการเขียนเพื่อป้องกันงานเก่าทับงานใหม่

พรีวิวและไฟล์ส่งออกใช้ `src/renderer.ts` ร่วมกัน นาฬิกาและวิดเจ็ตเป็น DOM อีกชั้นหนึ่ง การส่งออกจะรอฟอนต์ที่ต้องใช้ก่อนวาดภาพ อุปกรณ์ Apple ใช้ฟอนต์ระบบ ส่วนฟอนต์ไทยและญี่ปุ่นมี Noto Sans เป็น fallback โดยไม่แจกจ่าย SF Pro

ข้อมูลเก็บแยกตาม browser และ origin เช่น localhost กับ Network URL จะมีงานล่าสุดคนละชุด ไม่มีการซิงก์ข้ามเครื่อง การล้างข้อมูลเว็บไซต์ โหมดส่วนตัว หรือระบบคืนพื้นที่อาจลบงานได้ หากบันทึกไม่ได้จะแสดงสถานะให้ดาวน์โหลดไว้แทน

## ทดสอบ

```sh
npm test
npx playwright install chromium webkit
npm run test:e2e
npm run build
```

Unit tests ตรวจการครอปไม่ออกนอกภาพ ตำแหน่งองค์ประกอบทุกรุ่น เวลา สีข้อความ และการรับมือข้อมูลบันทึกที่เสียหาย

Browser tests ใช้ Chromium บน desktop และ WebKit จำลอง iPhone ตรวจอัปโหลด เลื่อน/ซูม ชื่อเพลงหลายภาษา ขนาด PNG จริง สีพิกเซลหลังครอป ภาพส่งออกเหมือนกันไม่ว่าจะเปิด/ปิดนาฬิกาจำลอง การกู้คืนงานหลัง reload และไฟล์รูปเสียหาย พร้อมตรวจว่าไม่มี JavaScript errors หรือ requests ไปยังเว็บไซต์อื่น

## ขอบเขตการใช้งาน

- ทดสอบผ่าน WebKit จำลอง iPhone แล้ว แต่การบันทึกลง Photos และตั้ง Lock Screen บน iPhone จริงยังต้องตรวจบนอุปกรณ์จริง
- นาฬิกาและวิดเจ็ตเป็นภาพจำลอง ตำแหน่งจริงขึ้นกับรุ่น iOS การปรับนาฬิกา วิดเจ็ต และการครอปตอนตั้งวอลเปเปอร์
- HEIC/HEIF ใช้ได้เฉพาะเมื่อเบราว์เซอร์ถอดรหัสได้ หากเปิดไม่ได้จะแนะนำให้แปลงเป็น JPG
- รูปที่เล็กกว่าขนาดส่งออกอาจไม่คม และอุปกรณ์หน่วยความจำน้อยอาจมีข้อจำกัดกับรูปขนาดใหญ่
- ประมวลผลในเครื่องไม่ได้หมายความว่าเปิดเว็บครั้งแรกแบบ offline ได้ เว็บไม่มี service worker สำหรับติดตั้งหรือ cache offline
- ฟอนต์และการเกลี่ยขอบอักษรอาจต่างกันเล็กน้อยระหว่างระบบปฏิบัติการตามสเปกที่ยืนยัน

โครงการนี้ไม่ได้เชื่อมกับ Apple Music และไม่ได้เป็นผลิตภัณฑ์ของ Apple
